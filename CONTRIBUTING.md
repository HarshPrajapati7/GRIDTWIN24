# Contributing

1. Open an issue describing the change and the test or evidence needed.
2. Keep the official Tomorrow's Load forecast path working independently of the dashboard, Gemma agent and hardware.
3. Do not commit organiser datasets, private meter data, API keys, MQTT credentials or customer data.
4. Add or update tests for forecast, scenario and tool behaviour.
5. Document any new feature's data requirements, assumptions and failure modes.
6. Never add an LLM tool that can bypass the physical hardware interlocks.
7. Label generated/demo data as synthetic and never report it as a benchmark result.

By submitting a contribution, you agree that it may be distributed under the project Apache-2.0 license unless the project maintainers explicitly state otherwise.
